# Μετάβαση περιβάλλοντος (staging → παραγωγή)

## Το πρόβλημα που λύνει

Το `index.html` δηλώνει το backend σε **τέσσερα** σημεία που πρέπει να αλλάξουν
μαζί:

| # | Σημείο | Τι σπάει αν μείνει πίσω |
|---|---|---|
| 1 | `const APP_ENVIRONMENT` | Καμία ένδειξη για το ποιο περιβάλλον τρέχει |
| 2 | `const SUPABASE_URL` | Η εφαρμογή γράφει σε λάθος βάση |
| 3 | `const SUPABASE_KEY` | Αποτυχία αυθεντικοποίησης |
| 4 | CSP `connect-src` (`https://` **και** `wss://`) | Η σελίδα φορτώνει κανονικά και **κάθε** κλήση προς τη βάση μπλοκάρεται σιωπηλά από τον browser |

Επιπλέον, τα (1)–(3) βρίσκονται μέσα σε inline `<script>` καρφιτσωμένο με
`'sha256-...'` στη CSP. Κάθε επεξεργασία τους ακυρώνει το hash και, χωρίς
επανυπολογισμό, ο browser **μπλοκάρει ολόκληρο το script** — λευκή οθόνη.

Πέντε χειροκίνητες αλλαγές, εκ των οποίων η μία απαιτεί υπολογισμό base64
sha256. Δεν είναι διαδικασία που αντέχει την ημέρα του go-live.

## Η διαδικασία

```sh
node tools/set-environment.mjs \
  --env production \
  --url https://<project-ref>.supabase.co \
  --key sb_publishable_XXXXXXXX

npm test
```

Η εντολή εκτελεί και τις πέντε αλλαγές σε μία κίνηση, επαληθεύει το
αποτέλεσμα **πριν** γράψει, και δεν αποθηκεύει τίποτα αν προκύψει
ασυνέπεια. Είναι ταυτοτική: δεύτερη εκτέλεση με τις ίδιες τιμές δεν αλλάζει
τίποτα.

Απορρίπτονται πριν γραφτούν: `http://`, host εκτός `*.supabase.co`, URL με
διαδρομή, secret key αντί publishable, άγνωστο όνομα περιβάλλοντος.

## Έλεγχος

```sh
npm run env:check
```

```
✓ staging · https://omncqldgtkdcjpqfwwlr.supabase.co · CSP και hashes συνεπή
```

Ο ίδιος έλεγχος τρέχει στο CI μέσω `tests/go-live-environment-switch.test.mjs`
και `tests/phase5-production-readiness.test.mjs`. Καμία μισή μετάβαση δεν
φτάνει στο `main`:

- URL αλλαγμένο, CSP όχι → αποτυχία
- CSP αλλαγμένη, σταθερές όχι → αποτυχία
- Ξεπερασμένο `sha256` hash → αποτυχία
- Υπολείμματα δεύτερου project στο αρχείο → αποτυχία
- Wildcard ή secret key → αποτυχία

## Τι **δεν** καλύπτει

Η βάση προορισμού πρέπει να έχει ήδη το σωστό schema
(`REQUIRED_SCHEMA_VERSION` στο `index.html`) και τα δεδομένα της, σύμφωνα με
το `ΒΗΜΑ4_ΜΕΤΑΒΑΣΗ_ΠΑΡΑΓΩΓΙΚΟΥ.md`. Το εργαλείο αλλάζει πού δείχνει η
εφαρμογή — όχι τι υπάρχει εκεί.
