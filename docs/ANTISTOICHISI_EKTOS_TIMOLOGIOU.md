# «Χρέωση ως»: αντιστοίχιση γραμμών εκτός τιμολογίου

## Τι άλλαξε

Μια γραμμή δελτίου **εκτός τιμολογίου** (ελεύθερη περιγραφή, δική της τιμή)
απαιτούσε αντιστοίχιση με **ακριβώς ίση** συμβατική αξία (±0,005 €). Στην πράξη
αυτό ήταν συχνά αδύνατο: τα συμβατικά είδη έχουν βήμα ποσότητας — π.χ. ακέραια
τεμάχια — οπότε καμία ποσότητα δεν έδινε ακριβώς την αξία της γραμμής. Το δελτίο
έμενε αδύνατο να εκδοθεί και η εφαρμογή παρέπεμπε ξανά και ξανά στο «⇄».

Πλέον η αντιστοίχιση **δεν χρειάζεται να βγάζει το ίδιο ποσό**. Αρκεί να δηλώνει
σε ποιο ή ποια είδη της σύμβασης χρεώνεται η γραμμή.

## Γιατί δεν χαλάει τα οικονομικά

Οι δύο απολογισμοί είναι εξαρχής χωριστοί:

| | Από πού προκύπτει | Τι επηρεάζει η αντιστοίχιση |
|---|---|---|
| **Χρήμα** (δεσμευμένα / συμβατικό υπόλοιπο) | `subtotal` του δελτίου, δηλαδή ποσότητα × τιμή κάθε γραμμής | **Τίποτα** |
| **Ποσότητες** ανά συμβατικό είδος | ποσότητες γραμμών + ποσότητες αντιστοίχισης | Τα πάντα |

Άρα από τη σύμβαση αφαιρείται πάντα η **πραγματική αξία της γραμμής**, ό,τι κι αν
λέει η αντιστοίχιση. Αυτό ίσχυε και πριν την αλλαγή· η απαίτηση ισότητας ήταν
πρόσθετος έλεγχος συνέπειας, όχι ο μηχανισμός της χρέωσης.

## Τι εξακολουθεί να ισχύει

1. **Κάθε γραμμή εκτός τιμολογίου με αξία χρειάζεται τουλάχιστον μία
   αντιστοίχιση.** Χωρίς αυτήν η χρέωση θα έμενε χωρίς συμβατικό έρεισμα. Ο
   έλεγχος γίνεται μόνο κατά την **έκδοση** — ως πρόχειρο η γραμμή αποθηκεύεται
   ελεύθερα.
2. **Το οικονομικό πλαφόν της σύμβασης παραμένει απαράβατο.** Το άθροισμα των
   δελτίων δεν ξεπερνά τη συμβατική καθαρή αξία.
3. **Το πλαφόν συμβατικής ποσότητας ανά είδος παραμένει απαράβατο.** Οι
   ποσότητες της αντιστοίχισης μετρούν κανονικά· υπερβολική αντιστοίχιση κόβεται
   με «Υπέρβαση συμβατικής ποσότητας».

## Τι βλέπει ο χρήστης

* Στη γραμμή: `⇄ αντιστοίχιση: 45,00 € / 47,30 € (−2,30 €)`. Κόκκινο μόνο όταν
  δεν υπάρχει καμία αντιστοίχιση.
* Στο «Υπόλοιπο σύμβασης»: ενημερωτικό (όχι κόκκινο) σημείωμα με τη συνολική
  διαφορά και τη διευκρίνιση ότι δεν εμποδίζει την έκδοση.
* Στο modal «Αντιστοίχιση»: η κάλυψη δεν βάφεται πια κόκκινη όταν δεν ταιριάζει
  ακριβώς — μόνο όταν δεν έχει επιλεγεί τίποτα.

## Πού υλοποιείται

| Σημείο | Αρχείο |
|---|---|
| Έλεγχος έκδοσης (browser) | `index.html` → `validate(o,forIssue)` |
| Ενημερωτικό σημείωμα υπολοίπου | `index.html` → `renderBalance()` |
| Modal αντιστοίχισης | `index.html` → `openMappingModal(line)` |
| Ατομικό RPC | `public.save_order_atomic` |
| Φύλακας δελτίου | `public.app_order_contract_financial_guard` |
| Migration | `supabase/migrations/202608290001_flexible_custom_mapping.sql` |
| Έλεγχοι | `tests/flexible-custom-mapping.test.mjs` |

Η δηλωμένη έκδοση schema παραμένει **36.6.6**: η αλλαγή χαλαρώνει έλεγχο και δεν
μεταβάλλει δομή, ώστε ήδη ανοιχτός client να συνεχίζει να λειτουργεί.

## Επαλήθευση παραγωγικού

Το `supabase/110_VERIFY_V36_6_5.sql` δεν αναζητά πλέον μηδενική διαφορά αξίας.
Ελέγχει `custom_charge_as_missing_mapping = 0` και αναφέρει τη μέγιστη διαφορά
αξίας ως πληροφορία.
